CoryPositioningOpen
NMS is a headquarters application, and that is its runway
The best way to describe NMS is as a "headquarters" application. It lives on a dedicated computer that's always on, and it manages a fleet of radios from there. That's a valuable thing. This is the same model used in some ultrawideband systems: the units in the field are simple and inexpensive, and the intelligence sits back at the central server. As part of a larger ground control station product, this architecture has a lot of runway. You could add monitoring, automation, and eventually AI-driven Sense and EW capabilities on top of it. Steven Griggs has mentioned interest in a GCS product, and this would be a natural foundation for it. Perhaps we throw in an optional tracking system module, too.
Where it stands. A product direction rather than a defect. Left open deliberately - a decision for the team, not something engineering can close.

The scenario we test against

Ten radios, two networks, eight reachable only over the air. Written as a customer journey with the failure built into it on purpose.

The rules. Ten real Doodle Labs radios, not a LIMA eval kit. The only radio anyone may plug an Ethernet cable into is the GCS radio. No command line at any point — web interface only.
Phase 1 Build it

Eight radios are already in drones and hard to reach by cable. Two are for ground control stations. Two networks, each one GCS and four drones.

  1. Designate 2 GCS radios and 8 drone radios. Firmware update all ten. Never connect to a drone radio over Ethernet — only through the GCS radio.
  2. Two networks:
    NetworkMesh IDPassword
    1Doodle1doodle1PASSWORD
    2Doodle2doodle2PASSWORD
  3. Simple Config:
    NetworkChannelBandwidthDevices
    12085 MHz10 MHz1 to 2
    21791 MHz10 MHz1 to 2
  4. An additional static IP on each drone radio:
    RadioAddressRadioAddress
    N1 drone 1192.152.1.2/16N2 drone 1192.152.2.2/16
    N1 drone 2192.152.1.3/16N2 drone 2192.152.2.3/16
    N1 drone 3192.152.1.4/16N2 drone 3192.152.2.4/16
    N1 drone 4192.152.1.5/16N2 drone 4192.152.2.5/16
  5. Serial / UART for the flight controller: 38400 baud on /dev/uart0.
  6. Install Sense licences.
  7. Configure Sense. A slave node also needs its thresholds set.
    Network 1 ACS listNetwork 2 ACS list
    1715/201800/20
    2500/102390/10
    1675/102335/20
    2210/202050/20

    Thresholds, both networks: packet loss 76%, busy time 78%, inactive time 4000 ms.

  8. Enable Sense. One drone radio and one GCS is enough.
  9. Add two more channels to both lists: 1668/10 and 2089/10.
  10. Disable Sense.
  11. Re-enable Sense, packet loss ratio 85%.
Phase 2 The wrong setting, and the first real test

Four drones and one GCS will not run. Doodle Labs says the wrong value was used in the Setup Wizard.

  • a. Change number of devices from “1 to 2” to “3 to 5”.
  • b. Then check everything from Phase 1 is still there. Sense? UART? IP addresses?
This is the point of the scenario. Changing one value must not silently discard the other twenty.
Phase 3 The customer is angry

“All my settings are gone and the mesh isn't working.” A field engineer attends. Large-node mesh performing badly.

  • a. Rebroadcast for self and others: 2
  • b. OGM interval: 2500 ms
  • c. Turn off TPC and ATPC
  • d. Transmit power: 23 dBm
Phase 4 WDS

The customer has heard WDS mode will fix a roaming problem.

  • a. Switch to WDS / AP mode.
  • b. Confirm every previously set setting is still correct.
Phase 5 Different firmware

Do not use WDS — try this other firmware instead.

  • a. Install a different firmware.
  • b. Set the whole of Phase 1 up again.
What we found checking the product against it. Simple Config — the screen the whole scenario runs on — is hidden in a customer build, so Phase 1 cannot be performed at all. The settings are not destroyed by us: our destructive path was removed some time ago, and the radio's own reload deletes its wireless configuration every time. Sense, UART, the extra address, TPC, ATPC and the rebroadcast counts all survive. Transmit power is destroyed every time and returns at the regulatory maximum. The 2500 ms OGM interval cannot be set by any tool — the radio recomputes it from the device count. That one is a firmware request.
